# CargoTech RAG corpus v1

Проверено: **06.08.2026**.

Набор предназначен только для двух сценариев MVP:

- `PAYMENT_DELAY` — претензия о просрочке оплаты;
- `LOADING_FAILURE` — непредоставление ТС / срыв погрузки на уровне AI-модуля.

Это не универсальная правовая база и не замена проверки юристом.

## Правило безопасности

`extra.auto_use=true` получают только нормы, которые допустимо автоматически извлекать для соответствующего сценария. Условные нормы имеют `auto_use=false` и текущий `RagSearchService` их не подмешивает:

- специальная неустойка по ч. 2 ст. 10 Закона № 87-ФЗ требует подтверждения договора транспортной экспедиции и контура «экспедитор → клиент»;
- части 1–3 ст. 34 Закона № 259-ФЗ требуют различать договор перевозки и договор фрахтования, полное непредоставление и опоздание;
- ч. 5 ст. 4 АПК РФ хранится только как workflow-норма и не должна автоматически превращаться в угрозу судом в тексте претензии.

## Договорные условия

Глобальный RAG не должен содержать вымышленные пункты конкретного договора. `ClaimAiRequestMapper` передает в AI подтвержденные структурированные поля карточки договора:

- срок оплаты и событие начала исчисления;
- договорную ставку неустойки, когда она заполнена;
- срок ответа на претензию.

Номер пункта оригинала не придумывается. Перед отправкой документа условия необходимо сверить с загруженным оригиналом договора.

## Быстрое развертывание

Из корня проекта:

```bash
sh scripts/deploy-rag.sh
```

Перед загрузкой скрипт валидирует JSON, затем пересобирает только `ai` и `claim`, заменяет старую демонстрационную коллекцию и выполняет два семантических smoke-теста.
